# Mobile navigation and creation controls

The user reported the navbar Create button overlapping on small screens and requested a review of team/project/task creation actions. After the audit, the user approved a **compact global Create menu on mobile, a compact brand, and labeled page-level create buttons**, with consistent sizing/spacing and the existing archived/read-only rules. This is a UI follow-up against user commit `055e0f8`; it does not add another release checkpoint or close release checkpoints 7–8.

## Findings and resulting behavior

- **Navbar overlap:** the full brand and right-side actions intersected at 320, 360 and 390 px in the baseline fixtures. The mobile brand and Create trigger are now compact, independently named icons with 44 px targets. The full brand and Create text return at 640 px. The right-side actions do not shrink into the brand; the left side can use remaining space for truncated breadcrumbs.
- **Long account names:** the account action's visible name is capped at 96 px at desktop/tablet widths, with the full name retained in the accessible control name and account menu. Notification and account controls use the same 44 px mobile / 36 px larger-screen rhythm. The mobile Workspace drawer trigger also has a 44 px target; its navigation behavior is retained.
- **Inconsistent creation actions:** Teams/Projects previously displayed generic Create labels, whereas the project header used Create Task with different geometry. Page headers, board/list empty states and the team switcher now reuse an entity-specific `CreateButton`: **Create team / Create project / Create task**, a plus icon, consistent spacing and rounded corners, 44 px on mobile and 36 px from 640 px upward. The team-count row can wrap; the project task action expands beside its separate archive control on mobile. The adjacent archive trigger is sized to align, with its existing confirmation/permissions intact.
- **Dialog controls:** shared Create/Cancel/Close targets are 44 px on mobile and 36 px on larger screens. Compact mobile padding gives fields more room while retaining a scrollable body and reachable footer. Dialog headings remain titles; action labels use sentence case. Validation, field rules, required indicators, pending locks, draft retention, errors and submission callbacks are unchanged.
- **Read-only consistency:** the global menu previously offered New Task in an archived/read-only project while the page hid its task action. The shortcut now uses the existing project permission helper and shared project-detail query key. It waits for team/project context and disables context-dependent creation after failed reads, including failures that retain stale cached data. Independent team creation remains available to global ADMIN/SUPER_ADMIN; project/task creation still requires the existing team management role. An archived project does not prevent creating another project in its active team. No backend permission or API contract changed.

The global trigger remains named **Create** for assistive technology and keyboard access when its visible text is hidden. Menu choices have explicit entity names. Existing permission-disabled choices remain visible rather than introducing a new discovery/navigation policy. The dialogs continue to use the current shadcn/Radix components; no dependencies were added or upgraded, and no new colors or application-wide button defaults were introduced.

## Verification

- **592 passing frontend tests in 59 files**, including 20 new creation-navigation/action cases. Tests cover active owners/admins, global roles without team editing roles, ordinary members, archived teams/projects, read-only projects, missing/loading/failed context, failures with retained cached data, scoped dialog opening and explicit page-action labels. Existing creation validation, pending locks, retry/draft retention, navigation and task-drag tests pass. Existing assertions were updated for the approved sentence-case action labels.
- Strict lint, TypeScript/production compilation, Prettier and Git whitespace checks pass. The existing large JavaScript chunk warning remains. No backend source, migration, deployment configuration or dependency changed, so backend suites and Docker images were not rebuilt for this input/layout batch.
- Headless Edge reviewed the actual frontend at **320, 360, 390, 414, 640, 768, 1024 and 1440 px** across Teams, team overview, Projects and project details: no navbar control intersections after the change. Create Team/Project/Task dialog footer/close actions remain inside 320×568 and 390×400 viewports and measure 44 px on mobile. Task fields below the fold remain in the scrolling form body; that is expected, not an off-screen footer defect.
- A long-name case at 768 px retains usable navbar actions/breadcrumb space. At 320 px in dark mode, the compact controls fit and a 99-count notification badge clears the neighboring account action. Touch opening of the global creation menu and canceling the team form succeeds. The archived-project case disables global Create task consistently with its missing local action. No browser page errors or attempted business writes were observed.

Browser checks used isolated API/auth fixtures because the saved bootstrap credentials were not accepted by the running instance. No credentials were changed or reset. The fixtures render the current components; they are layout/interaction evidence, not a new real-backend authorization test. No team/project/task was created or modified. Browser fixture data, before/after screenshots and sanitized logs are saved outside Git in the local mobile-create-review artifacts. The development-only React Query tool visible in some screenshots is not a production create control.

These bounded tests do not certify physical devices, Safari/iOS, a virtual keyboard, every translated label, load targets or production release acceptance. The short viewport tests simulate reduced available height, not an actual mobile keyboard. Wider project/header density and other previously recorded design choices remain separate scope decisions.

The assistant did not stage, commit or push; the pre-existing staged index is preserved. Suggested user commit after review: `fix: improve mobile navigation and creation actions`.
