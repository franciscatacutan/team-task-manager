# Project collaboration rules

- Never create Git commits or push changes. The user makes all commits.
- When an approved phase is verified and ready, summarize it and suggest a commit message for the user.
- Explain every change: what changed, why, which files control it, how to customize it, and how it was tested.
- Use `name` for task/project domain names across API contracts and frontend models; do not introduce a `title` alias for them.
- Work phase by phase. Obtain the user's approval before beginning a new phase or broadening its scope.
